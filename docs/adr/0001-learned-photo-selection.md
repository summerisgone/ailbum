# ADR-0001: Обучаемый отбор фотографий по решениям пользователя

- Статус: принято
- Дата: 2026-11-07
- План: [docs/plans/2026-11-07-decision-models.review.md](../plans/2026-11-07-decision-models.review.md)

## Контекст

Отбор кадров сейчас задаётся двумя фиксированными правилами:

- победитель группы похожих кадров - кадр с максимальным `quality`
  (0.8 резкость + 0.2 экспозиция, `src/ailbum/pipeline.py:288`). Глаза, улыбка,
  композиция и CLIP-эстетика уже считаются, но в выборе не участвуют;
- первичный выбор desktop - все победители групп (`src/ailbum/database.py:1273`);
  `target_count` на него не влияет.

Пользователь правит выбор в desktop, но сохраняется только итог: снятие отметки
удаляет строку из `photo_selections`, и отрицательный сигнал теряется. Нетронутый
первичный выбор совпадает с текущим правилом, поэтому по одному итогу нельзя отличить
"пользователь согласен" от "пользователь не смотрел".

Данных мало: сотни явных решений на один каталог. Проект намеренно обходится без
тяжёлых ML-зависимостей (кластеризация реализована без scikit-learn).

## Решение

1. **Журнал решений.** Новая таблица `selection_events` (схема v11): запуск,
   изображение, действие (`add` / `remove` / `seed`), источник (`auto` / `manual` /
   `backfill`), время. Пишется из `set_desktop_favorite` только при реальном изменении
   и из первичного заполнения. Для старых запусков события один раз восстанавливаются
   из разницы между `photo_selections` и `photo_analysis.selected`.
2. **Метки только из явных действий.** Попарные метки "A лучше B" берутся только из
   групп, в которых пользователь хотя бы раз что-то менял. Метки "взят / не взят" для
   альбома берутся только из запусков, где не меньше 5 ручных событий. Нетронутые
   рекомендации меткой не считаются.
3. **Единый вектор признаков.** Около 20 признаков кадра: качество, эстетика,
   композиция, цвет, лица (число, закрытые глаза, улыбка, известные люди), положение
   в группе. Пропуски заполняются нулём с флагом наличия. Вектор строится одинаково
   из `PhotoRecord` и из строк БД, у него есть фиксированная `feature_version`.
4. **Модель.** Логистическая регрессия с L2 на NumPy: попарный режим для выбора
   внутри группы, поточечный - для альбома. Нормализация, веса и метрики хранятся в
   таблице `ranking_models`.
5. **Защита от регрессии.** Ранкер обучается при не меньше 50 парах не меньше чем
   из 2 запусков. Модель активируется, только если точность leave-one-run-out не ниже,
   чем у `max(quality)` на тех же группах; дубликаты по `sha256` не разносятся между
   обучением и проверкой. Если модели нет или её `feature_version` не совпадает,
   работает `max(quality)`, а `quality` разбивает ничьи.
6. **Подбор под `target_count`.** Первичный выбор desktop - ровно `target_count`
   кадров. Жадный подбор: оценка модели (без модели - `quality`) минус 0.5 x
   максимальное CLIP-сходство с уже взятыми, сначала по одному кадру на сюжет, пока
   хватает мест. Без эмбеддингов разнообразие обеспечивается через
   `similar_cluster` и сюжет. Действие `selection.autofill` заполняет свободные места
   и не трогает ручные кадры.
7. **Обучение вручную.** `ailbum ranking train`, `ailbum ranking status` и
   `ailbum ranking evaluate`. В манифесте анализа записывается, чем сделан выбор.

## Рассмотренные альтернативы

- **LightGBM / градиентный бустинг.** Лучше ловит нелинейности, но добавляет
  зависимость, а на сотнях меток переобучается. Можно вернуться к нему через extra
  `ml`, когда данных станет больше.
- **Обучаться на итоговом `photo_selections` целиком.** Тогда модель выучит текущую
  эвристику из-за смещения от первичного выбора.
- **Подобрать вручную веса в `quality`.** Это дешевле, но веса будут одни на всех
  пользователей, и их придётся каждый раз настраивать руками.
- **Автоматическое обучение перед каждым `analyze`.** Отложено: поведение анализа
  менялось бы незаметно для пользователя.

## Последствия

- Без модели победители групп остаются прежними, существующие тесты pipeline не
  меняются.
- Поведение desktop меняется: новый запуск открывается с `target_count` кадрами, а
  не со всеми победителями групп.
- Схема БД переходит на v11; миграция только добавляет таблицы и строки.
- Качество выбора растёт по мере того, как пользователь правит выбор. Пока данных
  мало, поведение совпадает с текущим.
- При изменении признаков нужно поднять `feature_version` и переобучить модель;
  старая модель автоматически перестаёт применяться.

## Вне рамок решения

Обучаемые границы сюжетов (`src/ailbum/stories.py:255` - глобальная сегментация, а
не решения по парам; сначала стоит подобрать константы через `evaluate-stories`),
обучаемый порог размытия, неявные сигналы просмотра, общая модель для нескольких
пользователей.
