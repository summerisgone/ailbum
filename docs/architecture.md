# Архитектура Ailbum

Конвейер хранит результаты каждого запуска в SQLite и экспортирует версионированный
`analysis.json`. Это позволяет добавлять следующие этапы без повторного чтения и
анализа оригиналов.

```text
каталог фото
    │
    ├─ загрузка + EXIF ── метаданные времени
    ├─ кэш SHA-256 ────── готовые CV-признаки для повторного запуска
    ├─ оценка качества ── резкость, экспозиция, итоговый quality
    ├─ композиция ─────── saliency/лица, трети, заполненность, кроп, цвет
    ├─ CLIP (опционально) ─ эстетика + zero-shot объекты и сцены
    ├─ признаки кадра ─── pHash + цвет ── быстрые дубли и кандидаты
    │                              └───── SIFT + RANSAC ── поворот/кадрирование
    └─ лица ───────────── detector + alignment + embedding ──── кластеры лиц
                              │          │                            │
                              │          ├─ состояние каждого глаза  │
                              │          └─ выражение + улыбка        │
                              └─ classic или YuNet/SFace ────────────└─ постоянные Person

Сюжеты: время + GPS + люди + сцены
    │
SQLite + analysis.json + selection.csv + desktop UI
```

## Границы модулей

- `io.py` — поиск файлов, загрузка с EXIF-поворотом, время съёмки.
- `metadata.py` — полное извлечение файловых, EXIF, GPS и контейнерных метаданных.
- `database.py` — схема SQLite, каталог изображений и история анализов.
- `cv/quality.py` — технические метрики и переиспользуемая пирамида превью.
- `cv/aesthetics.py` — композиция, главный объект и цветовые метрики без DNN.
- `stories.py` — временная сегментация и поиск семантической смены сцены.
- `story_naming.py` — названия сюжетов по нескольким кадрам через локальную VL-модель
  LM Studio с детерминированным фолбэком.
- `cv/semantics.py` — опциональная CLIP-оценка эстетики и семантические теги.
- `cv/similarity.py` — глобальные и геометрические признаки, сравнение и группы
  похожих кадров.
- `cv/faces.py` — взаимозаменяемые бэкенды лиц.
- `feature_cache.py` — версионированный файловый кэш CV-признаков по SHA-256.
- `cv/clustering.py` — кластеризация без тяжёлой зависимости от scikit-learn.
- `people.py` — контактные листы всех уникальных лиц одного человека.
- `pipeline.py` — оркестрация и стабильная схема результатов.
- `cli.py` — точка запуска анализа, индексации и обслуживания каталога.
- `desktop_bridge.py` — постоянный JSON-lines RPC между Electron и Python/SQLite.
- `desktop_job.py` — отдельный процесс длительной индексации и анализа со
  структурированными событиями этапов и прогресса для Electron.
- `desktop/` — изолированный Electron renderer; получает данные и локальные
  изображения только через preload IPC.

## Раскладка альбома

Пакет `src/ailbum/layout/` строит развороты из выбранных фото и похожих кадров.
Вычисления детерминированы: повторный запуск на тех же данных даёт тот же результат.

- `types.py`, `templates.py` - общие датаклассы, форматы страницы и каталог шаблонов.
- `crop.py` - подбор кропа ячейки с защитой лиц и корешка.
- `allocation.py` - распределение разворотов по сюжетам.
- `facts.py` - пул кадров и защищаемые области из SQLite; кэш детектора в `image_object_scans`.
- `composer.py` - выбор кадров, шаблона и ячеек для разворота.
- `assistant.py` - превью вариантов и необязательный выбор через LM Studio.
- `store.py` - таблицы `layouts`, `layout_spreads`, `layout_placements` и JSON-контракт.
- `service.py` - `preflight` (без открытия изображений) и `generate`.
- `editing.py` - ручные правки: фото, обмен ячеек, шаблон, кроп, пересборка.
- `cv/objects.py` - детектор объектов YOLOX на OpenCV DNN.

Граница с Electron: `desktop_bridge.py` обслуживает действия `layout.*`, `desktop_job.py`
запускает `generate` отдельным процессом. Флаг `stale` вычисляется при чтении раскладки
по хэшу выбранных кадров.

## Desktop и граница доверия

Renderer работает с `contextIsolation`, без Node.js и прямого доступа к диску.
Electron main-процесс запускает один Python bridge и последовательно передаёт ему
команды чтения/записи. Оригиналы публикуются renderer-у по закрытому протоколу
`ailbum-media://` только после того, как их ID и путь пришли из текущей базы.
Кропы лиц формирует Python bridge через Pillow с применением EXIF-ориентации и
отдаёт main-процессу по запросу; Electron держит ограниченный LRU-кеш миниатюр.
Длительные задания не блокируют bridge: main-процесс запускает для них отдельный
`desktop_job`, читает JSON-lines события прогресса и передаёт их renderer через IPC.

Сетка виртуализирована по строкам: количество DOM-узлов зависит от размера окна,
а не от размера каталога. Нативное декодирование Chromium и `loading=lazy`
ограничивают число одновременно загруженных оригиналов.

Для DNN-бэкенда лицо один раз выравнивается по пяти ориентирам YuNet. Тот же
фрагмент поступает в SFace, классификатор каждого глаза `open-closed-eye-0001` и
Progressive Teacher/MobileFaceNet, который возвращает семь выражений: `angry`,
`disgust`, `fearful`, `happy`, `neutral`, `sad`, `surprised`. Вероятность `happy`
также экспортируется как `smile_probability`. В классическом режиме выражение
оценивается по нормализованному фрагменту лица, а центры глаз уточняются каскадом.

## Сходство фотографий

Первый уровень сравнивает 64-битный pHash и нормализованную HSV-гистограмму. Он
дешёвый, но чувствителен к изменению границ и ориентации кадра. Второй уровень
извлекает локальные SIFT-признаки, оставляет взаимные пары по Lowe ratio и
проверяет единую геометрию сцены гомографией RANSAC.

`geometric_scene_overlap` объединяет три компонента: число подтверждённых точек,
долю геометрически корректных соответствий и площадь их распределения на обоих
кадрах. Поворот и кадрирование не штрафуются сами по себе. Значение `>= 0.55`
считается совпадением сюжета. Перед дорогим сопоставлением используется широкий
prefilter (`pHash <= 24` или HSV-сходство `>= 0.65`), поэтому случайные пары до
SIFT/RANSAC не доходят. Геометрические кандидаты дополнительно ограничиваются
соседними позициями временной ленты или небольшим интервалом времени съёмки;
дешёвое точное совпадение pHash/HSV по-прежнему проверяется для всех пар.

## Следующие этапы

1. Формировать события по времени, GPS, людям и визуальному сходству.
2. Строить сюжет как последовательность событий: завязка, развитие, кульминация,
   финал; ограничивать повторы людей и сцен.
3. Добавить интерактивное подтверждение выбора в терминале и экспорт в структуру
   альбома, сохраняя решения пользователя для последующего обучения ранжирования.
