# Раскладка альбома: дизайн

## 1. Требования и решения

От пользователя:

- Меню "Создать раскладку": ориентация (вертикальная/горизонтальная) - число разворотов - число фото на коллаже.
- Фото группируются по разворотам согласно шаблонам коллажей (6 примеров, см. раздел 2).
- Из похожих кадров выбирается тот, что лучше подходит под формат ячейки (квадрат, вертикаль, горизонталь).
- Лица и важные объекты не обрезаются при подгонке.
- Развороты кратны сюжетам.
- Источник: выбранные фото плюс похожие кадры из их групп; замена видна в UI.
- Первая версия: просмотр и правки, без экспорта.
- Важные объекты: лица плюс лёгкий ONNX-детектор.

Допущения (менять легко, это константы и данные):

- "Кратны сюжетам": один разворот принадлежит одному сюжету, сюжет занимает целое число разворотов. Исключение: сюжет меньше минимума коллажа или разворотов меньше, чем сюжетов; тогда соседние сюжеты объединяются, и разворот получает предупреждение.
- "Кол-во фото на коллажах": диапазон от-до, значения 1-6, по умолчанию 3-6. Равные границы дают фиксированное число.
- Форматы: вертикальная страница 210x297 мм, горизонтальная 297x210 мм. Вылет 3 мм, безопасная зона 3 мм от обреза, зазор 5 мм, защитная полоса корешка 8 мм с каждой стороны. Значения сняты со скриншотов.
- На запуск анализа одна раскладка; новая заменяет прежнюю после подтверждения.

Вне первой версии: экспорт JPEG/PDF, ручная правка распределения разворотов по сюжетам, проверка DPI, текст на разворотах.

## 2. Шаблоны

Шаблон - дерево разрезов в долях разворота, поэтому геометрия не дублируется в TypeScript: Python отдаёт готовые прямоугольники. `V(a, ...)` режет по ширине, `H(a, ...)` по высоте, `C` - ячейка. Разрез 0.5 верхнего уровня совпадает с корешком.

| id | Фото | Вертикальный альбом | Источник |
|---|---|---|---|
| `full` | 1 | `C` (через корешок) | добавлен |
| `pages` | 2 | `V(.5, C, C)` | добавлен |
| `page_2h` | 3 | `V(.5, C, H(.5, C, C))` | пример 2 |
| `grid_2x2` | 4 | `H(.5, V(.5, C, C), V(.5, C, C))` | пример 3 |
| `wide_3` | 4 | `V(.65, C, H(1/3, 2/3: C, C, C))` | пример 4 |
| `inset_1_2` | 4 | `V(.5, C, H(.55, C, V(.5, C, C)))`, поля 6 мм | пример 5 |
| `grid_65_35` | 4 | `H(.5, V(.65, C, C), V(.65, C, C))` | пример 6 |
| `page_2_2` | 5 | `V(.5, C, V(.5, H(.5, C, C), H(.5, C, C)))` | добавлен |
| `page_2_3` | 6 | `V(.5, C, V(.5, H(.5, C, C), H(1/3, 2/3: C, C, C)))` | пример 1 |

Асимметричные шаблоны (`page_*`, `wide_3`, `inset_1_2`) получают зеркальный вариант с суффиксом `_m`.

Горизонтальный альбом (разворот около 2.8:1) использует те же деревья, кроме `grid_2x2` и `grid_65_35`: две широкие полосы дают слишком вытянутые ячейки, поэтому они заменены на `row_4` `V(.25, .5, .75: C, C, C, C)` и `page_3` `V(.5, C, V(1/3, 2/3: C, C, C))`.

Ячейки, касающиеся края, идут до вылета. Ячейка, пересекающая корешок, несёт `spine_band`; ячейка `inset_*` не касается края.

## 3. Алгоритм

Детерминированный конвейер, повторный запуск с теми же данными даёт тот же результат:

```text
photo_selections + похожие -> PhotoFacts -> StoryGroup -> allocate_spreads
    -> compose (DP по времени: кадры + шаблон + ячейка + кроп)
    -> топ-3 варианта разворота -> LM Studio (опционально) -> layout_* таблицы
```

### 3.1 Единицы выбора

Единица - группа похожих (`similar_cluster`) либо одиночный кадр. Кандидаты: выбранные кадры группы и невыбранные неразмытые соседи. Кадры с ошибкой и отсутствующие файлы исключаются. Из группы в альбом попадает один кадр; если единиц меньше минимума разворотов, выбранные кадры группы становятся отдельными единицами. Соседа предпочитаем только при заметном выигрыше: бонус выбранному кадру +0.15 к fit.

Размеры кадра учитывают EXIF: при `orientation` 5-8 ширина и высота меняются местами. Координаты `faces` и `main_subject` уже в повёрнутом кадре.

### 3.2 Защищаемые области

| Источник | Область | Вес | Жёсткая |
|---|---|---|---|
| Лицо (площадь >= 5% крупнейшего лица кадра) | bbox + 35% вверх, 20% по бокам, 15% вниз | 1.0 | да |
| Лицо фона (< 5%) | bbox | 0.2 | нет |
| Человек (COCO `person`) | bbox | 0.6 | нет |
| Животное, транспорт и прочие COCO-классы с уверенностью >= 0.5 | bbox | 0.5 | нет |
| `main_subject` из saliency (только если нет лиц и объектов) | bbox | 0.3 | нет |

Лица берутся по отдельности, а не объединением `main_subject`: группа людей по краям кадра иначе потребовала бы сохранить весь кадр.

### 3.3 Кроп

Окно с пропорцией ячейки перебирается по масштабам {1.0, 0.9, 0.8} и 11 позициям по каждой свободной оси:

- `visible`: часть окна, попадающая в безопасную зону ячейки.
- `cover(r)`: доля области `r` внутри `visible`.
- Нарушение: жёсткая область с `cover < 0.98` или пересекающая `spine_band`.
- `fit = 0.55*scale^2*retained + 0.45*(1 - soft_loss) - 0.02*center_dist - 0.5*[есть нарушение]`, ограничено 0..1.
- `retained = min(a_photo/a_cell, a_cell/a_photo)`, `soft_loss` - взвешенная доля потерянных мягких областей, `center_dist` - расстояние центра окна от центра тяжести областей (центра кадра, если областей нет).

Нарушение штрафуется, а не запрещается: раскладка собирается всегда, а ячейка получает предупреждение `face_cut` или `face_on_spine`.

### 3.4 Сюжеты и развороты

1. Сюжет с числом единиц меньше `min_photos` сливается с соседом, ближайшим по времени.
2. Пока групп больше `spread_count`, сливается соседняя пара с наименьшей суммой (при равенстве первая).
3. Динамика распределяет `s_i >= 1` при `sum(s_i) = spread_count`, минимизируя `sum(s_i*(n_i/s_i - t)^2)`, где `t = sum(n)/spread_count`; `s_i*min_photos > n_i` штрафуется на 1000 за каждую недостающую единицу.

### 3.5 Компоновка внутри группы

1. Если единиц больше `s*max_photos`, отбрасываются единицы с наименьшим рангом; они возвращаются как `unplaced`.
2. Единицы сортируются по времени. Динамика делит их на `s` последовательных кусков допустимого размера; состояние включает последний шаблон, повтор шаблона подряд стоит 0.15.
3. Для куска и шаблона назначение единиц ячейкам ищется перебором по битовой маске. Значение: `сумма area_i*(fit + 0.25*rank)`, где `area_i` - доля площади ячейки; лучший кадр группы выбирается для каждой ячейки отдельно. Так крупная ячейка получает сильный кадр, а похожий кадр - нужную ориентацию.
4. `rank`: `0.45*quality + 0.35*aesthetic_or_quality + 0.1*min(1, smiling/faces) - 0.2*(closed_eyes > 0) + 0.2*selected`, ограничено 0..1.

Если единиц не хватает, кусок ниже минимума допустим и помечается `underfilled`.

## 4. AI-ассистент

Решение: нужен, но как необязательный редактор поверх детерминированного движка.

Движок считает геометрию и ограничения: это точные вычисления, с которыми локальная VL-модель справляется хуже и медленнее. Модель решает только то, что не выражается формулой: какой из готовых вариантов разворота лучше читается как история и как композиция. Для каждого разворота с несколькими вариантами:

- рендерится лист из вариантов A/B/C (Pillow, не больше 896 px);
- модель получает лист и название сюжета, возвращает `{"choice":"B","reason":"..."}`;
- ответ вне допустимых вариантов, таймаут или недоступный сервер оставляют вариант движка.

Варианты заранее проходят ограничения, поэтому ответ модели не может обрезать лицо или выдумать ID фото. Отклонена генерация всей раскладки моделью: маленькая модель плохо удерживает длинные списки ID и не гарантирует ограничения.

Настройки берутся из конфигурации запуска анализа (`lmstudio_url`, `lmstudio_model`), как у `StoryNamer`. Переключатель в мастере: "AI-редактор", режимы `auto` (если сервер доступен) и `off`. Время: один запрос на разворот, поэтому задание идёт в фоне с прогрессом и отменой.

## 5. Детектор объектов

YOLOX-S из `opencv_zoo` (`object_detection_yolox_2022nov.onnx`, Apache 2.0, 36 МБ, SHA-256 `c5c2d13e59ae883e6af3b45daea64af4833a4951c92d116ec270d9ddbe998063`). Проверено: загружается в OpenCV 4.14 проекта, выход `(1, 8400, 85)`, 0.1 с на кадр.

- Вход: RGB, letterbox 640x640, отступ 114, без нормализации; порог 0.35, NMS 0.5.
- Запуск лениво при генерации и только для кадров пула.
- Кэш в `image_object_scans` по `image_id`, модели и `sha256` файла.
- Нет файла модели: шаг пропускается с предупреждением, защита остаётся на лицах и saliency.

## 6. Данные и контракт

Схема 11 в `database.py`:

```sql
image_object_scans(image_id FK, detector_model, sha256, objects_json, scanned_at,
                   PRIMARY KEY (image_id, detector_model))
layouts(id PK, run_id UNIQUE FK, orientation, spread_count, min_photos, max_photos,
        selection_hash, assistant_model, unplaced_json, warnings_json, created_at, updated_at)
layout_spreads(id PK, layout_id FK, position, template_id, story_ids_json,
               warnings_json, assistant_reason, UNIQUE (layout_id, position))
layout_placements(spread_id FK, cell_index, image_id FK, crop_x, crop_y, crop_w, crop_h,
                  fit, warnings_json, replaced_image_id, PRIMARY KEY (spread_id, cell_index))
```

`selection_hash` - SHA-256 отсортированных `image_id` выбора. Несовпадение показывает, что раскладка устарела; автоматически она не пересчитывается.

JSON `layout.get` (`null`, если раскладки нет):

```json

 "max_photos": 6, "stale": false, "assistant_model": null, "warnings": [],
 "unplaced": [{"image_id": 9, "reason": "capacity"}],
 "format": {"spread_w_mm": 426, "spread_h_mm": 303, "bleed_mm": 3, "safe_mm": 3},
 "spreads": [{"id": 5, "position": 1, "template_id": "page_2h", "story_ids": [1],
   "story_title": "Ужин", "warnings": [], "assistant_reason": null,
   "cells": [{"index": 0, "x": 0.0, "y": 0.0, "w": 0.494, "h": 1.0,
              "crosses_spine": false,
              "placement": {"image_id": 7, "crop": {"x": 0.1, "y": 0.0, "w": 0.6, "h": 1.0},
                            "fit": 0.82, "warnings": [], "replaced_image_id": null}}]}]}
```

`cells.x..h` - доли прямоугольника с вылетом. `crop` - доли повёрнутого кадра.

RPC (bridge, через preload):

| Действие | Параметры | Результат |
|---|---|---|
| `layout.preflight` | `run_id, orientation, spread_count, min_photos, max_photos` | `{pool_count, unit_count, story_count, min_needed, max_used, allocation: [{story_ids, title, spreads, units}], errors, warnings}` |
| `layout.get` | `run_id` | контракт выше |
| `layout.templates` | `orientation, photo_count` | `[{id, photo_count, cells: [{index, x, y, w, h}]}]` |
| `layout.alternatives` | `spread_id, cell_index` | `[{image_id, fit, warnings, in_selection}]`, лучшие первыми, не больше 24 |
| `layout.set_photo` | `spread_id, cell_index, image_id` | контракт `layout.get` |
| `layout.swap_cells` | `spread_id, cell_a, cell_b` | контракт |
| `layout.set_template` | `spread_id, template_id` | контракт |
| `layout.set_crop` | `spread_id, cell_index, crop` | контракт |
| `layout.recompose_spread` | `spread_id` | контракт |

Длительная генерация: новый вид задания `layout` в `desktop_job` через существующий канал прогресса: `--run-id`, `--params` (JSON с параметрами preflight и `assistant`), этапы "Анализ объектов", "Компоновка", "AI-редактор".

Ошибки: preflight возвращает `errors`, если `spread_count < 1`, `min_photos > max_photos`, границы вне 1-6 или единиц меньше `spread_count`. Генерация с такими ошибками завершается `ValueError` с тем же текстом. Правка с несуществующим ID даёт `ValueError` через RPC. `set_crop` принимает окно только в пределах кадра с пропорцией ячейки (допуск 1%).

## 7. Интерфейс

Новый раздел навигации "Раскладка" (`LayoutGrid`), файлы `desktop/src/layout/`:

- **Мастер**: три шага на одном экране, как в запросе. Ориентация - две карточки. Число разворотов - поле с шагом, подсказка равна целой части `единицы/4`. Фото на коллаже - два поля от/до. Сводка обновляется через preflight: "63 кадра, 11 сюжетов, нужно 30-60", список сюжетов с числом разворотов, ошибки блокируют кнопку "Создать".
- **Редактор**: лента разворотов сверху вниз с заголовком сюжета и подписью "Разворот N". Разворот рендерится абсолютными ячейками в пропорции формата; направляющие вылета, безопасной зоны и корешка как на примерах, переключаются.
- **Правки**: клик по ячейке открывает панель справа: кандидаты с fit и значком "из похожих", кнопки смены шаблона того же числа фото, "Пересобрать разворот". Перетаскивание фото в ячейке двигает кроп, перетаскивание между ячейками меняет кадры местами.
- **Предупреждения**: значок на ячейке (`face_cut`, `face_on_spine`), на развороте (`merged_stories`, `underfilled`), баннер "Выбор изменился, пересоздать?". Заменённый похожим кадр помечается в ячейке и панели.

Кадры идут через существующие `mediaUrl`/`originalUrl`. Лента виртуализируется по строкам только если появятся проблемы со скоростью; десятки разворотов DOM выдерживает.

## 8. Тестирование

- Чистые модули (`templates`, `crop`, `allocation`, `composer`): точные значения и инварианты: сумма ячеек плюс зазоры покрывает разворот, лицо не попадает в полосу корешка, число разворотов равно запрошенному, каждый кадр использован один раз, порядок времени соблюдается, повтор запуска идентичен.
- База: миграция с 10 на 11 на существующей базе, каскадное удаление.
- Ассистент: мок ответа: неверный выбор, мусор, таймаут оставляют вариант движка.
- Интеграция: SQLite с синтетическими запусками и файлами, generate, get, правки.
- UI: `npm run build` и ручной прогон в приложении на реальной базе.
