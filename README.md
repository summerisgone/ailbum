# Ailbum

Локальный CLI-конвейер многоступенчатого отбора фотографий для альбома. Первый этап:

- помечает нечёткие фотографии по дисперсии лапласиана;
- группирует серии и визуально похожие кадры по pHash/цвету и геометрическому
  перекрытию сцены SIFT/RANSAC;
- выбирает самый качественный резкий кадр внутри каждой группы;
- находит лица и группирует похожие лица;
- определяет открытость каждого глаза, выражение лица и вероятность улыбки;
- оценивает композицию: правило третей, заполненность, свободное пространство и
  риск неудачного кропа главного объекта;
- измеряет цветовой баланс и гармонию палитры;
- опционально использует CLIP для нейросетевой оценки эстетики, тегов и
  сохраняемого визуального эмбеддинга каждого кадра;
- определяет сюжеты глобальной сегментацией визуальных эмбеддингов с учётом
  времени, места и повторяющихся людей;
- сохраняет постоянных людей и узнаёт их в следующих запусках;
- сохраняет полный JSON-манифест и плоскую CSV-таблицу для проверки;
- ведёт локальный SQLite-каталог путей, EXIF/GPS и истории CV-анализов.

Оригиналы не изменяются и не копируются.

## Стек

- Python 3.10+ — простой переносимый CLI и хорошая CV-экосистема;
- OpenCV — признаки изображений, детекция и эмбеддинги лиц;
- NumPy — численные операции и кластеризация;
- Pillow — корректное применение EXIF Orientation;
- Transformers + PyTorch (опционально) — локальные CLIP-эмбеддинги и
  zero-shot-классификация;
- LM Studio + компактная VL-модель (опционально) — содержательные названия сюжетов;
- pytest + Ruff — тесты и статические проверки.
- Electron + React + TypeScript — локальный интерфейс быстрого ручного отбора.

В базовом режиме лица обрабатываются локальным Haar-детектором и классическими
HOG/цветовыми признаками. Для реальных альбомов рекомендуется один раз загрузить
YuNet + SFace: они заметно устойчивее к ракурсу и освещению. Все вычисления после
загрузки моделей выполняются локально.

## Установка

```bash
uv sync --extra dev
uv run ailbum --help
```

Чтобы включить vision-метрики, установите ML-зависимости:

```bash
uv sync --extra dev --extra ml
```

При первом запуске Transformers загрузит указанную модель в локальный кеш. После
этого инференс выполняется локально. По умолчанию используется
`openai/clip-vit-base-patch32`; вместо ID можно передать локальный каталог через
`--clip-model`.

Опциональные модели лиц и мимики:

```bash
uv run ailbum download-models
```

Команда загружает YuNet, SFace, классификатор открытых/закрытых глаз и модель
семи выражений лица. Файлы ONNX сохраняются в `models/` и не добавляются в Git.

## Запуск

```bash
uv run ailbum analyze ./data --output ./output
```

Потребовать CLIP-бэкенд явно (команда завершится с понятной ошибкой, если модель
или ML-зависимости недоступны):

```bash
uv run ailbum analyze ./data -o ./output --semantic-backend clip
```

В режиме `auto` композиционные и цветовые метрики считаются всегда, а при
недоступном CLIP нейросетевые поля остаются `null`; причина записывается в
`semantic_error` манифеста. CLIP-оценка здесь является относительной zero-shot
оценкой по позитивному и негативному эстетическим промптам, а не калиброванным
баллом NIMA.

Проверить спорную пару отдельно и увидеть обе метрики вместе со временем расчёта:

```bash
uv run ailbum compare ./data/first.jpg ./data/second.jpg
```

По умолчанию база создаётся в `.ailbum/ailbum.sqlite3`. Можно отдельно собрать
метаданные без CV-анализа и просмотреть каталог:

```bash
uv run ailbum index ./data
uv run ailbum db stats
uv run ailbum db list --limit 20
uv run ailbum db show 1
```

Просмотр людей, присвоение имени, исправление группировки и контактный лист:

```bash
uv run ailbum people list
uv run ailbum people show 3
uv run ailbum people name 3 "Анна"
uv run ailbum people merge 3 8 12
uv run ailbum people compose 3 --output ./output/people/anna.jpg
```

Принудительно использовать лёгкий офлайн-бэкенд:

```bash
uv run ailbum analyze ./data -o ./output --face-backend classic
```

После запуска:

- `output/analysis.json` содержит конфигурацию, сводку, группы похожих фото,
  группы людей, `story_groups` и записи каждого кадра с `story_id`;
- каждая запись кадра содержит `composition`, `color` и `semantics`: координаты
  главного объекта нормализованы к `0…1`, как и все итоговые оценки;
- каждое лицо в JSON содержит `eyes` с состоянием и вероятностью открытости
  обоих глаз, а также `expression` с классом, вероятностями семи эмоций и
  `smile_probability` (вероятность класса `happy`);
- `output/selection.csv` удобно сортировать и проверять вручную;
- `.ailbum/ailbum.sqlite3` хранит пути, SHA-256, файловые свойства, полные
  разобранные EXIF/GPS, параметры камеры, историю метрик, лица, их эмбеддинги и
  постоянные сущности людей;
- `selected=true` означает лучший резкий кадр в своей группе; одиночный резкий
  кадр также выбирается;
- `is_blurry=true` означает отбраковку по текущему порогу.

## Настройка порогов

Порог резкости зависит от камеры и размера изображения. Значение по умолчанию
`100` — стартовая эвристика, а не универсальная граница. Посмотрите столбец
`sharpness` в CSV и повторите запуск, например:

```bash
uv run ailbum analyze ./data -o ./output --sharpness-threshold 65
```

Основные параметры доступны через `ailbum analyze --help`. Для DNN-бэкенда
типичный порог сходства лиц ниже, чем для классического; CLI выбирает безопасное
начальное значение, его можно переопределить `--face-similarity`.

Границы сюжетов строятся детерминированно глобальной сегментацией временной ленты.
Алгоритм минимизирует неоднородность CLIP-эмбеддингов целых отрезков, а
названия scene-тегов не управляют компоновкой. GPS, интервалы и повторяющиеся люди
служат дополнительными универсальными признаками. Пороги доступны через
`--story-gap-minutes`, `--story-continuity-minutes`,
`--story-semantic-break-minutes` и `--story-max-duration-hours`.

Ручная Markdown-разметка используется только как внешний набор метрик и никогда
не читается при обычном формировании сюжетов:

```bash
uv run ailbum evaluate-stories ./stories.md --database .ailbum/ailbum.sqlite3
```

Отчёт включает pairwise и B³ precision/recall/F1, полноту каждого размеченного
сюжета, чистоту предсказанных групп и сходство названий.

Для содержательных названий режим `auto` использует локальную мультимодальную
модель LM Studio, если сервер запущен, и безопасно возвращается к правилам, если
он недоступен. Пример настройки компактной модели:

```bash
lms get qwen/qwen3-vl-2b -y
lms server start
uv run ailbum analyze ./data --story-naming-backend auto
```

Явный режим `--story-naming-backend lmstudio` завершит анализ с понятной ошибкой,
если сервер или модель недоступны. URL и модель меняются через `--lmstudio-url` и
`--lmstudio-model`.

Для семантических тегов доступны `--semantic-threshold` и `--semantic-top-k`.
Теги vision-модели подходят для поиска сюжетов, но не заменяют детектор с
точными bounding box каждого предмета.

Глобальные pHash и цветовая гистограмма быстро находят почти одинаковую
компоновку. `geometric_scene_overlap` подтверждает один сюжет при повороте,
другой ориентации, кадрировании или небольшом сдвиге камеры. Метрика лежит в
диапазоне `0…1`, начальный порог — `0.55`; он меняется через
`--photo-geometric-similarity`. Для полного отключения более дорогого этапа есть
`--no-geometric-similarity`.

В рабочем конвейере геометрия вычисляется каскадом: дешёвые признаки отбрасывают
явно чужие пары, уже найденные pHash-дубли не пересчитываются через RANSAC. Для
воспроизводимого сравнения скорости обеих метрик:

```bash
uv run python scripts/benchmark_similarity.py ./data --repetitions 3
```

Классификаторы мимики подключаются автоматически, если их ONNX-файлы находятся
в `models/`. Если они ещё не загружены, анализ лиц сохраняет обратную
совместимость: поля `eyes` и `expression` будут `null`.
По умолчанию атрибуты не оцениваются у лиц меньше 64 пикселей: для глаз в таком
фрагменте уже недостаточно исходных деталей. Порог меняется через
`--min-attribute-face-size`.

Подробности: [архитектура](docs/architecture.md) и
[схема локальной базы](docs/database.md).

## Desktop-интерфейс

После анализа можно открыть виртуализированную сетку фотографий. Ручное избранное
хранится в SQLite отдельно от автоматического `selected`, поэтому повторная работа
в интерфейсе не меняет результаты CV-конвейера.

```bash
cd desktop
npm install
npm run dev
```

По умолчанию приложение открывает `.ailbum/ailbum.sqlite3`. Другую базу можно
выбрать в шапке или передать через `AILBUM_DATABASE`. Для production-сборки
renderer используется `npm run build`; `npm start` собирает и запускает Electron.
Кнопка-шестерёнка открывает панель управления: в ней можно открыть или создать
SQLite-базу, перетащить папки с фотографиями для индексации и повторно запустить
анализ последнего источника. Импорт и анализ выполняются в отдельном процессе;
панель показывает реальный этап, имя текущего файла и счётчик обработанных кадров.
В карточках отображаются CLIP-балл эстетики и основной тег сцены, а строка поиска
ищет также по тегам объектов и сюжетов. Серии похожих кадров в сетке свёрнуты в
стопки с количеством фотографий; клик раскрывает серию, после чего её можно снова
свернуть отдельной кнопкой. Клик по обычной карточке открывает оригинал в
полноэкранном просмотрщике с навигацией стрелками и закрытием по `Esc`. Клик по
миниатюре в нижней ленте прокручивает виртуальную сетку к соответствующему сюжету;
активный поисковый фильтр при этом сбрасывается. Существующие базы получают сюжеты
при первом открытии без повторного CV-анализа.

Раздел «Люди и лица» открывается второй кнопкой бокового меню. В нём можно
переименовать человека, перенести отдельное лицо к другой записи, отвязать его или
создать из него нового человека. Изменения сразу сохраняются в SQLite; кропы лиц
учитывают EXIF-ориентацию исходных JPEG.
